# API reference

The REST/JSON contract between the SPA and the API. It is the **only** coupling between the two
(see [architecture](architecture.md#the-only-coupling-is-the-http-contract)).

The machine-readable contract is the OpenAPI 3.1 document generated by the API from the
controllers. It is available when `OpenApi:Enabled` is `true`, which is the case in Development and
in the docker-compose demo:

- OpenAPI JSON: `http://localhost:8080/openapi/v1.json` (docker) / `http://localhost:5079/openapi/v1.json` (`dotnet run`)
- Interactive UI (Scalar): `http://localhost:8080/scalar`

The examples below are real responses from the running API; ids, tokens and trace ids are shortened.

## Conventions

| Topic | Convention |
|---|---|
| Base path | `/api` |
| Format | JSON, camelCase property names. Requests send `Content-Type: application/json`. |
| Authentication | `Authorization: Bearer <token>` on every endpoint except register, login, `/health` and the OpenAPI endpoints. |
| Ownership | The user is always taken from the token. No endpoint accepts a user id. |
| Ids | GUIDs (version 7). Route ids are constrained to GUIDs (`{id:guid}`); anything else is `404 Http.NotFound`. |
| Timestamps | ISO 8601 with offset, UTC (`2026-10-31T23:26:06.7575156+00:00`). |
| Errors | `application/problem+json` ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)) with an extra, stable **`code`**. Clients branch on `code`, never on `detail`. |
| Validation | The API reports **one** error per request (the first rule that fails). See [known issues](known-issues.md). |

### Error shape

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.10",
  "title": "Conflict",
  "status": 409,
  "detail": "A grocery item with this name already exists in your list.",
  "traceId": "00-6a970fb98d277edfe3e4a0832b836cea-bd5e84273e213ea2-00",
  "code": "GroceryItems.DuplicateName"
}
```

`detail` is safe to show to the user. `traceId` matches the server logs.

## Endpoints

| Method | Path | Auth | Success | Errors |
|---|---|---|---|---|
| `POST` | `/api/auth/register` | anonymous | `201` `AuthResponse`, `Location: /api/users/me` | `400`, `409` |
| `POST` | `/api/auth/login` | anonymous | `200` `AuthResponse` | `400`, `401` |
| `GET` | `/api/users/me` | bearer | `200` `UserResponse` | `401` |
| `GET` | `/api/grocery-items` | bearer | `200` `GroceryItemResponse[]` | `401` |
| `GET` | `/api/grocery-items/{id}` | bearer | `200` `GroceryItemResponse` | `401`, `404` |
| `POST` | `/api/grocery-items` | bearer | `201` `GroceryItemResponse`, `Location: /api/grocery-items/{id}` | `400`, `401`, `409` |
| `DELETE` | `/api/grocery-items/{id}` | bearer | `204` | `401`, `404` |
| `PUT` | `/api/grocery-items/{id}/basket` | bearer | `204` | `401`, `404` |
| `DELETE` | `/api/grocery-items/{id}/basket` | bearer | `204` | `401`, `404` |
| `GET` | `/health` | anonymous | `200` `Healthy` (text) | `503` `Unhealthy` |

There is no logout endpoint: logging out means the client discards its token
([ADR 0003](adr/0003-jwt-bearer-and-client-side-logout.md)).

### `POST /api/auth/register`

Creates an account and signs the user in (the response carries a token).

| Field | Rules |
|---|---|
| `username` | required; 3–50 characters after trimming; unique (case-insensitive) |
| `fullName` | required; at most 100 characters after trimming |
| `password` | required; 8–128 characters |

```http
POST /api/auth/register
Content-Type: application/json

{ "username": "alice", "fullName": "Alice Smith", "password": "Sup3rSecret!" }
```

```http
HTTP/1.1 201 Created
Location: /api/users/me
Content-Type: application/json; charset=utf-8

{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJhdWQiOi…",
  "expiresAtUtc": "2026-11-01T00:26:06.0968696+00:00",
  "username": "alice",
  "fullName": "Alice Smith"
}
```

Errors:

| Status | `code` | When |
|---|---|---|
| 400 | `Auth.UsernameRequired` | username missing or blank |
| 400 | `Auth.UsernameLength` | not 3–50 characters |
| 400 | `Auth.FullNameRequired` | full name missing or blank |
| 400 | `Auth.FullNameTooLong` | more than 100 characters |
| 400 | `Auth.PasswordRequired` | password missing or empty |
| 400 | `Auth.PasswordLength` | not 8–128 characters |
| 400 | `Request.Invalid` | body is not valid JSON (see below) |
| 409 | `Auth.UsernameTaken` | username exists (also on a concurrent registration) |

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "Bad Request",
  "status": 400,
  "detail": "Password must be between 8 and 128 characters.",
  "traceId": "00-e168…-00",
  "code": "Auth.PasswordLength"
}
```

### `POST /api/auth/login`

| Field | Rules |
|---|---|
| `username` | required (trimmed) |
| `password` | required |

Only presence is checked; applying the registration rules here would hint at what is wrong.

```http
POST /api/auth/login
Content-Type: application/json

{ "username": "alice", "password": "Sup3rSecret!" }
```

```http
HTTP/1.1 200 OK

{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJhdWQiOi…",
  "expiresAtUtc": "2026-11-01T00:26:06.0968696+00:00",
  "username": "alice",
  "fullName": "Alice Smith"
}
```

Errors:

| Status | `code` | When |
|---|---|---|
| 400 | `Auth.UsernameRequired` / `Auth.PasswordRequired` | field missing or blank |
| 400 | `Request.Invalid` | malformed JSON |
| 401 | `Auth.InvalidCredentials` | unknown username **or** wrong password (deliberately the same, with similar timing) |

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.2",
  "title": "Unauthorized",
  "status": 401,
  "detail": "The username or password is incorrect.",
  "traceId": "00-1f0e…-00",
  "code": "Auth.InvalidCredentials"
}
```

#### Token contents

The token is a JWT signed with HMAC-SHA256. Decoded payload:

```json
{
  "aud": "GroceryList.Web",
  "iss": "GroceryList.Api",
  "exp": 1793492766,
  "iat": 1793489166,
  "nbf": 1793489166,
  "sub": "01a19448-def8-7061-81c4-6283cace4013",
  "unique_name": "alice",
  "name": "Alice Smith",
  "jti": "9b7bc23d-4c1f-4f73-8997-dee192a853a9"
}
```

`sub` is the user id that every protected endpoint uses. The lifetime is `Jwt:ExpirationMinutes`
(60 by default); `expiresAtUtc` in the response equals `exp`.

### `GET /api/users/me`

Returns the user the token belongs to. The SPA calls it to restore a session after a reload.

```http
GET /api/users/me
Authorization: Bearer eyJhbGciOi…
```

```json
{ "id": "01a19448-def8-7061-81c4-6283cace4013", "username": "alice", "fullName": "Alice Smith" }
```

| Status | `code` | When |
|---|---|---|
| 401 | `Auth.Unauthenticated` | no token, invalid signature, expired, wrong issuer or audience |
| 401 | `Users.CurrentUserNotFound` | the token is valid but its user no longer exists |

### `GET /api/grocery-items`

The current user's items, ordered by creation time, then name. No pagination.

```json
[
  {
    "id": "01a19448-e1a5-7ee3-8a82-c81f9cdc685d",
    "name": "Milk",
    "quantity": 2,
    "isInBasket": false,
    "createdAtUtc": "2026-10-31T23:26:06.7575156+00:00"
  }
]
```

| Status | `code` | When |
|---|---|---|
| 401 | `Auth.Unauthenticated` | no or invalid token |

### `GET /api/grocery-items/{id}`

One of the current user's items. It is also the target of the `Location` header returned when an item is created.

```http
GET /api/grocery-items/01a19462-e3b3-7abc-a1ac-098ef61d3583
Authorization: Bearer eyJhbGciOi…
```

```http
HTTP/1.1 200 OK

{
  "id": "01a19462-e3b3-7abc-a1ac-098ef61d3583",
  "name": "Milk",
  "quantity": 2,
  "isInBasket": false,
  "createdAtUtc": "2026-10-31T23:54:31.2191444+00:00"
}
```

| Status | `code` | When |
|---|---|---|
| 401 | `Auth.Unauthenticated` | no or invalid token |
| 404 | `GroceryItems.NotFound` | no such item **or it belongs to another user** |

### `POST /api/grocery-items`

| Field | Rules |
|---|---|
| `name` | required; at most 100 characters after trimming; unique per user (case-insensitive) |
| `quantity` | integer ≥ 1; optional, defaults to `1` |

```http
POST /api/grocery-items
Authorization: Bearer eyJhbGciOi…
Content-Type: application/json

{ "name": "Milk", "quantity": 2 }
```

```http
HTTP/1.1 201 Created
Location: /api/grocery-items/01a19448-e1a5-7ee3-8a82-c81f9cdc685d

{
  "id": "01a19448-e1a5-7ee3-8a82-c81f9cdc685d",
  "name": "Milk",
  "quantity": 2,
  "isInBasket": false,
  "createdAtUtc": "2026-10-31T23:26:06.7575156+00:00"
}
```

New items start with `isInBasket: false`. The `Location` header points to the new item
([`GET /api/grocery-items/{id}`](#get-apigrocery-itemsid)).

| Status | `code` | When |
|---|---|---|
| 400 | `GroceryItems.NameRequired` | name missing or blank |
| 400 | `GroceryItems.NameTooLong` | more than 100 characters |
| 400 | `GroceryItems.QuantityInvalid` | quantity below 1 |
| 400 | `Request.Invalid` | malformed JSON, or `quantity` not an integer |
| 401 | `Auth.Unauthenticated` | no or invalid token |
| 409 | `GroceryItems.DuplicateName` | the user already has an item with this name ("milk" = "Milk") |

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "Bad Request",
  "status": 400,
  "detail": "Quantity must be at least 1.",
  "traceId": "00-55ef…-00",
  "code": "GroceryItems.QuantityInvalid"
}
```

### `DELETE /api/grocery-items/{id}`

Removes the item. `204 No Content` on success.

| Status | `code` | When |
|---|---|---|
| 401 | `Auth.Unauthenticated` | no or invalid token |
| 404 | `GroceryItems.NotFound` | no such item **or it belongs to another user** |

### `PUT /api/grocery-items/{id}/basket` and `DELETE /api/grocery-items/{id}/basket`

Tag (put in the basket) and un-tag (put back). The basket is modelled as a sub-resource of the
item ([ADR 0007](adr/0007-basket-as-sub-resource.md)): `PUT` makes "item is in the basket" true,
`DELETE` makes it false. Both have no body, return `204 No Content`, and are **idempotent**:
repeating either is harmless, which suits retries on flaky mobile connections.

```http
PUT /api/grocery-items/01a19448-e1a5-7ee3-8a82-c81f9cdc685d/basket
Authorization: Bearer eyJhbGciOi…
```

```http
HTTP/1.1 204 No Content
```

| Status | `code` | When |
|---|---|---|
| 401 | `Auth.Unauthenticated` | no or invalid token |
| 404 | `GroceryItems.NotFound` | no such item **or it belongs to another user** |

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
  "title": "Not Found",
  "status": 404,
  "detail": "The grocery item was not found.",
  "traceId": "00-244e…-00",
  "code": "GroceryItems.NotFound"
}
```

### `GET /health`

Anonymous liveness and database check for container orchestrators and load balancers. Returns
`200` with the text `Healthy`, or `503` with `Unhealthy` when SQL Server is unreachable.

## Error code catalogue

Business errors are defined once, in `GroceryList.Application/Common/Errors.cs`; framework errors
are coded in `GroceryList.Api/DependencyInjection.cs` and `Errors/GlobalExceptionHandler.cs`.

| `code` | Status | Meaning |
|---|---|---|
| `Auth.UsernameRequired` | 400 | Username is required. |
| `Auth.UsernameLength` | 400 | Username must be between 3 and 50 characters. |
| `Auth.FullNameRequired` | 400 | Full name is required. |
| `Auth.FullNameTooLong` | 400 | Full name must be at most 100 characters. |
| `Auth.PasswordRequired` | 400 | Password is required. |
| `Auth.PasswordLength` | 400 | Password must be between 8 and 128 characters. |
| `Auth.UsernameTaken` | 409 | The username is already taken. |
| `Auth.InvalidCredentials` | 401 | The username or password is incorrect. |
| `Auth.Unauthenticated` | 401 | Missing, invalid or expired token (framework challenge, `WWW-Authenticate: Bearer`). |
| `Auth.Forbidden` | 403 | Reserved for framework 403s; no endpoint produces it today. |
| `Users.CurrentUserNotFound` | 401 | The token is valid but its user no longer exists. |
| `GroceryItems.NameRequired` | 400 | Name is required. |
| `GroceryItems.NameTooLong` | 400 | Name must be at most 100 characters. |
| `GroceryItems.QuantityInvalid` | 400 | Quantity must be at least 1. |
| `GroceryItems.NotFound` | 404 | The item does not exist or belongs to another user. |
| `GroceryItems.DuplicateName` | 409 | An item with this name already exists in the user's list. |
| `Request.Invalid` | 400 | The body could not be read (malformed JSON, wrong types). Includes MVC's `errors` dictionary. |
| `Http.NotFound` | 404 | No such route (for an authenticated caller; see [known issues](known-issues.md)). |
| `Http.MethodNotAllowed` | 405 | The route exists but not with this method. |
| `Http.Error` | other | Any other framework-generated status. |
| `Server.UnexpectedError` | 500 | Unhandled exception; details only in Development. |

The frontend adds one client-side code, `Network.Unreachable` (status `0`), when the API cannot be
reached.

`Request.Invalid` example (malformed JSON):

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "$.username": ["Expected depth to be zero at the end of the JSON payload. …"]
  },
  "traceId": "00-e894…-00",
  "code": "Request.Invalid"
}
```
